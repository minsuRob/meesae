## 결론

1. **신고 대상이다.** 서버(`updateLocation`)가 계정에 묶인 GPS 좌표를 받는 순간 개인위치정보를 다루는 위치기반서비스사업이다.
   구 단위로 뭉개서 내보내도 수집 단계에서 이미 해당한다 (해설서 57쪽: 단말 밖으로 안 보내야만 신고 제외).
2. **등록(위치정보사업)은 아니다.** OS 위치 기능으로 받은 좌표를 자기 서비스에 쓰는 앱은 위치기반서비스사업으로 분류된다 (해설서 31쪽).
   개인위치정보사업 등록은 법인만 가능.
3. **개인사업자도 신고할 수 있다.** 사업자등록이 먼저다. 1인 창조기업·소상공인이면 사업 개시 후 1개월 안에 간이신고(제9조의2)로 된다.
   다만 원스토어는 출시 때 신고필증을 요구하므로 출시 전에 신고하는 쪽을 권한다.
4. **미신고는 형사처벌** (제40조 제2호: 3년 이하 징역 또는 3천만원 이하 벌금). 2021년 방통위는 채팅앱 90곳을 미신고로 수사의뢰했다.
5. **신고보다 무거운 것은 실시간 위치공유다.** 상대에게 원 좌표가 그대로 가는 제3자 제공인데, 지금은 별도 동의도 매회 통보도 없다. 출시 전에 반드시 고친다.
6. 최근 제재의 대부분은 처리방침 미공개(201건)·약관 필수항목 누락(147건) 과태료다 (2026-04, ⚠️ 언론). 페이지 두 개가 가장 싼 방어다.

## 1. 법 구조

법률 제21066호(2025-10-01 시행) · 시행령 대통령령 제36084호(2026-02-10 시행) 기준.

| 구분 | 위치정보사업 | 위치기반서비스사업 |
|---|---|---|
| 정의 | 위치정보를 수집해 LBS 사업자에게 제공 (제2조 제6호) | 위치정보를 이용해 서비스 제공 (제2조 제7호) |
| 절차 | 개인위치정보: 등록(법인만) · 사물위치정보: 신고 | 개인위치정보 대상일 때만 신고 (제9조) |
| 미이행 벌칙 | 5년 이하 / 5천만원 이하 (제39조 제1호) | 3년 이하 / 3천만원 이하 (제40조 제2호) |
| meesae | 해당 안 됨 (자체 측위 인프라 없음) | **해당** |

**정의 (제2조).** 위치정보는 전기통신설비로 측위된 특정 시점의 장소 정보. 개인위치정보는 그것만으로 누군지 몰라도
다른 정보와 용이하게 결합해 특정 개인의 위치를 알 수 있는 것을 포함한다. 사업자가 실제로 결합하지 않아도 결합할 수 있으면
개인위치정보다 (해설서 FAQ 1, 156쪽). 반대로 이메일·전화·기기값 없이 임의 index 로만 구분하는 날씨 앱은 신고 대상이 아니다 (57쪽).

**구 단위·거리 버킷은?** 직접 다룬 해석 사례는 찾지 못했다. 측위 좌표에서 만들어져 식별 가능한 프로필에 붙으므로
개인위치정보일 가능성이 높다 (정밀도를 낮추면 정의에서 빠진다는 근거가 원문·해설서에 없다).
구별 인원수 지도는 개인과 연결되지 않은 집계라 아닐 여지가 있지만, 인원 1명인 칸은 재식별 위험이 있다.

**2024~2026 개정.** 의무 내용을 바꾼 법률 개정은 없다.

- 2025-10-01: 방송통신위원회 → 방송미디어통신위원회(방미통위) 명칭 변경
- 2026-02-10: 신고 수리 권한을 방송미디어통신사무소장에 위임 (시행령 제37조의2)
- 2024-04-23: 신고 시 확인 서류가 '주민번호 제외 사업자등록증명'으로
- 제도 골격은 2022-04-20 시행 개정(개인위치정보사업 등록제, 보유목적·기간 동의, 파기, 매출 3% 과징금)이 마지막이다
- 개인정보위 이관 같은 계류 법안은 1차 자료로 확인하지 못했다 ⚠️

## 6. 코드에서 고칠 곳

조사 단계라 코드는 건드리지 않았다. 출시 차단 순서.

**A. 실시간 위치공유** — `functions/src/api/share.ts`, `src/features/chat/LocationShareView.tsx`, `firestore.rules:107-112`

1. 상대에게 공유 시작을 알리고(시스템 메시지 `systemKey` + 푸시) 상대가 명시적으로 수락해야 상대 위치 업로드를 시작.
   지금은 화면을 열면 20초마다 자동 업로드(`LocationShareView.tsx:45-53`)
2. 매회 통보: 시작할 때 제공자 본인에게 "누구에게·언제까지·무슨 목적" 알림. 세션당 1회로 충분한지는 자문
3. `blockUser` 와 대화 `closedBy` 에서 공유 즉시 종료. `updateSharedLocation`(`share.ts:54-60`)과 Rules 에서 닫힌 대화 거부
4. 만료 즉시 `positions` 삭제 (Firestore TTL 또는 만료 시점 정리). 지금은 hourly 정리라 10~70분 남음 (`triggers/scheduled.ts:21,28`)

**B. 동의와 고지**

1. 위치 동의 화면: 가입 약관과 분리된 체크박스, 거부해도 가입 가능(일부 동의 유보). 동의 기록(버전·시각)을 `users_private` 에,
   서버(`updateLocation`·`startLocationShare`)가 동의 없으면 거부
2. 약관·개인정보 처리방침·위치기반서비스 약관 페이지와 링크. 지금 `sign-in.tsx:105-107` 의 수동 동의 문구(`ko.ts:39`)를 체크박스 + 링크로
3. `app.json:50-55` 권한 문구 "정확한 위치는 다른 사람에게 공개되지 않아요" 는 실시간 공유와 모순 → 수정. `ko.ts:52` 도 같음
4. 설정에 위치 동의 철회 → `users_private.location` 즉시 삭제 + 공개 지역 필드 제거

**C. 확인자료와 파기**

1. 이용·제공사실 확인자료 컬렉션(예: `location_logs`): 누가·언제·무슨 목적·누구에게. 좌표는 넣지 않는다. 6개월 TTL. 서버만 쓰기
2. 보유기간을 정하고 지키기: `users_private.location` 원 좌표가 필요한지 다시 볼 것 (거리 버킷용이면 geohash 6~7자리로 충분할 수 있다)
3. 장부 `locationReward` 의 `refId: regionKey` 를 빼거나 기간 후 파기
4. `region_stats.center` 를 사용자 좌표 대신 행정구역 중심(지오코더 결과)으로

**D. 기타**

1. `updateLocation` 이 온보딩 전에도 돈다(`location.ts:25`) → 연령 확인 뒤로
2. 연령 하한 `MIN_AGE = 18`(`shared/onboarding-schema.ts:29`). 청소년보호법의 청소년은 만 19세 미만(19세가 되는 해 1월 1일을 맞은 사람 제외).
   데이팅 앱은 청소년이용불가가 요구되므로(원스토어, lbsc 추가자료) 기준을 맞춰야 한다 → 자문
3. 역지오코딩에 원 좌표 대신 geohash 6자리 중심을 보내기 (외부 전송 최소화, 캐시 키와도 맞음)
4. 지도에서 인원 k명 미만 지역은 숨기거나 "몇 명" 으로 뭉치기
5. 거리 버킷 반복 조회 제한 (같은 대상에 대한 위치 변경 후 재조회 빈도)

## 8. 법률 자문이 필요한 지점

1. 구 라벨·거리 버킷을 다른 회원에게 보이는 것이 제19조 제2·3항의 제3자 제공인지 (그렇다면 매회 통보 대상)
2. 실시간 공유의 '매회' 단위 — 세션당 1회 통보로 되는지, 모아서 통보 동의를 어떻게 설계할지
3. OS 위치 기능 기반 구조가 신고만으로 되는지 공식 확인 (해설서 28쪽은 직접 수집하면 두 사업 모두 해당한다고도 적음) — 센터 서면 질의 권장
4. 1인 창조기업·소상공인 해당 여부와 사업 개시일 (베타·무료 공개 포함 여부)
5. 데이팅 앱의 청소년유해매체물 추가자료와 연령 하한 (만 18 → 청소년보호법 기준)
6. 확인자료 보존기간(6개월 권고 고시 원문)과 개인정보보호법상 접속기록 의무의 관계, 위치 인증 좌표 파기 vs 별도 동의 보유
7. 처리 기간·수수료, 2026-02-10 이후 실제 수리 기관
8. 계류 개정안 (의안정보시스템 직접 확인)
